## 2. 进程边界与启动

- **Main（`src/main`）**：组合桌面服务，掌握文件系统、原生对话框、模型凭据、任务、变更账本及导出副作用。打开的文稿在主进程有对应的 `DocumentSession`。
- **Preload（`src/preload/index.ts`）**：通过 `contextBridge` 暴露 `window.api`。`invoke()` 解包 IPC 错误，并保留供界面分支使用的错误码；监听事件时返回注销回调。它不是任意通道代理。
- **Renderer（`src/renderer`）**：Vue、Pinia 和 CodeMirror 负责用户交互和活动缓冲区。组件调用 `window.api`，不直接读写磁盘，也不持有模型密钥。
- **Shared（`src/shared`）**：保存跨层契约、输入 schema、错误类型和纯文本算法。类型描述数据形状；执行时仍以 IPC、schema 和服务校验为准。

`src/main/index.ts` 处理单实例与启动文件参数；`bootstrap()` 准备应用目录、权限与 CSP，加载配置与持久化服务，创建主窗口和托盘，安装资源协议、IPC 与事件转发，并按配置恢复工作区和打开的文稿。首启演示数据由 `app/demo.ts` 准备。渲染入口 `src/renderer/main.ts` 创建 Vue 应用和 Pinia；`App.vue` 负责初始化状态、订阅广播和协调根级快捷键。窗口关闭有询问、隐藏到托盘、退出三条路径，不应等同于关闭文稿标签。

### 三种消息方向

| 方向 | 入口 | 用途 |
| --- | --- | --- |
| Renderer → Main | `window.api.<域>.<方法>()` → Preload `invoke()` → `registerIpc()` | 打开、保存、配置、Agent、导出等请求；主进程验证来源并转发给服务。 |
| Main → Renderer 广播 | `IPC.events` → Preload 订阅 → `App.vue` 与状态库 | 任务增量、文稿变动与冲突、工作区变化、设置更新等。 |
| Main → Renderer 请求/响应 | `EditorBridge` → `IPC.bridge.request` → `EditorHost.vue` → `IPC.bridge.response` | 读取编辑缓冲区、应用编辑、定位源码。按请求 ID 配对；未确认不代表已应用。 |

## 4. 文稿：打开、输入、保存与恢复

1. **打开**：文件对话框或工作区文件列表进入 `DesktopAPI.documents`。`DocumentService` 读取字节、记录原始换行和 BOM，并创建或复用 `DocumentSession`。快照进入 `useDocumentsStore`，`EditorHost.vue` 挂载活动正文。把文件拖到标签栏时，`CenterPanel.vue` 用 `webUtils.getPathForFile` 取本地路径，经 `documents.openDropped` 打开（拖放属于显式授权，不受工作区白名单限制；扩展名、存在性与体积仍由 `DocumentService` 校验），随后自动进入锁定阅读态并收起 AI 面板。
2. **输入与同步**：CodeMirror 事务触发文本回调 → `onEditorText()` 更新本地标签 → `queueSync()` 调度 `flush()` → `documents.update(documentId, text, baseRevision)` → Main 更新会话。批量同步与界面快照合并要避免旧响应覆盖仍在编辑的正文。元素面板点击或拖入片段时，`EditorController.insertSnippet()` 负责插入并回传表情的源码区间，`EmojiPicker.vue` 据此在表情下方弹出可搜索的全部简码，选中后用 `replaceRange()` 替换该区间；面板随编辑区滚动重定位，点击外部、Esc、切换文稿或锁定都会收起。
3. **呈现**：实时模式由 `livePreviewExtension()` 给 Markdown 源码加装饰和 Widget；源码模式保留标记，分屏预览由 `MarkdownPreview.vue` 单独渲染，并按滚动比例同步。大纲通过 `shared/markdown/outline.ts` 从源码计算，不从 Widget DOM 反推。`ui.contentWidth` 只影响实时模式的正文列宽（默认居中 / 铺满 / 较窄居中），由 `markdown.css` 的 `.mode-live.width-*` 覆盖 CodeMirror 注入的 `margin: 0`。`ui.locked` 通过 `EditorController.setLocked()` 切到只读，并让 `shouldShowSource()` 恒为 false、行内标记全部隐藏，Widget 也不再响应“点击回源码”。锁定不写 localStorage：`ui.locked` 默认 false，打开或切换文稿时由 `App.vue` 的 `activeId` 监听重置，避免锁定跨文件延续。为了让渲染页能像普通网页一样框选复制，锁定时会临时关掉 `drawSelection()` 并摘下 CodeMirror 的 `selectionchange` 观察器（解锁时恢复），保留浏览器原生选区；`EditorHost` 在复制事件里输出成稿文字与 HTML，避免 CodeMirror 按源码选区覆写剪贴板。
4. **保存**：手动或自动保存先收敛渲染端待同步正文，再交给 `DocumentService.save()`；没有路径则打开另存为。常规保存比较磁盘指纹与正文，按原格式将 LF 正文编码为磁盘字节，再以临时文件和重命名写入。`expectedRevision` 用于报告保存时版本差异，不是普通保存的拒绝条件。
5. **外部变更**：工作区监听和窗口重新聚焦可触发 `checkExternal()`。可重载时刷新会话；有未保存内容时通过冲突事件提示用户选择重新载入、覆盖或另存。
6. **草稿恢复**：未保存编辑可形成 `sessions/` 的恢复记录。下次启动由 `recoveryList()` 列出草稿，可恢复到会话或主动丢弃。此流程与 AI 事务的 `changes.restore()` 不同。

| 核心字段 | 维护时应区分 |
| --- | --- |
| `documentId` / `absPath` / `relativePath` | 前者标识会话；绝对路径由 Main 管理；工作区相对路径供文件树与已授权目标定位。 |
| `revision` / `contentHash` | 分别标识会话修订和归一化正文。变更提案使用两者共同保护规划基线。 |
| `diskFingerprint` / `lastSavedHash` | 前者基于原始磁盘字节，后者基于最近接受的 LF 正文，用途不同。 |
| `attached` / `existsOnDisk` / `dirty` | 分别描述是否附加到渲染标签、是否有磁盘文件及是否有未保存正文；三者不能互相替代。 |
| `from` / `to` | 原始 Markdown 的 UTF-16 半开区间，不是字节偏移，也不是预览 HTML 的索引。 |

## 5. 显式 Agent：从提示到事务

### 5.1 任务与工具

1. `AiDock.vue` 收集提示、作用范围、参考材料、附件、风格及模型选择。`useAgentStore` 提交 `agent.start`，`AgentController.start()` 检查输入和文本能力，并尝试同步活动文稿。
2. `AgentController.run()` 汇集文稿、大纲、选区和来源上下文，由 `buildSystemPrompt()` 编排为系统提示。`ProviderService.adapterFor()` 选择离线或兼容适配器；后者将流式内容归一化为 `ProviderEvent`。密钥只用于 Main 内的调用。
3. 控制器逐轮消费文本和工具请求，广播带任务 ID、序列号的 `TaskEvent`。不支持工具调用的模型仍可给出文字建议；工具执行可返回结果、用户澄清请求或待审阅提案。
4. `AgentTools.execute()` 检查工具及其目标，按任务允许的范围读取文稿、章节、来源等。提案工具把模型输入交给 `ChangeService.createProposalFromModel()`，不是直接调用写盘函数。澄清由 `agent.answer` 恢复，取消通过任务的中止信号传播。

### 5.2 规划、审阅、应用与恢复

| 步骤 | 实现 |
| --- | --- |
| 创建提案 | `ProposalSchema` 校验结构；变更服务验证目标和业务约束，记录风险、操作、来源摘要、`proposalDigest` 与状态。表格还要通过形状校验。 |
| 构建审阅 | `review()` 按文件分组，`planOperation()` 把章节锚点或区间映射到源码，更换文本时检查旧文本断言。共享编辑函数生成候选正文，`buildDiff()` 提供行级差异。 |
| 获得授权 | 审阅窗口传回提案 ID 和 `proposalDigest`。开启当前文稿低风险自动应用时，满足条件的编辑任务可由控制器调用相同的 `accept()`；拒绝只改变提案状态。 |
| 复核与分批 | `accept()` 检查待处理状态、摘要和适用的来源摘要，建立事务。`prepareTextBatches()` 同步目标会话，重新核对修订、哈希和文本区间，按文稿合批。目标文本计划失败不会执行目标修改。 |
| 写入和落账 | 按文本修改 → 新建 → 删除执行，备份必要内容并记录各步骤。附加标签经 `EditorBridge.apply()` 交给渲染端应用，回传正文后合入会话；未附加且有路径的会话走主进程写盘。标签内容已被修改不等于已保存到磁盘。 |
| 处理失败与恢复 | 失败后停止后续执行，已应用、失败和未执行的步骤分别记录。`restore(transactionId)` 依据账本、备份和当前状态尝试比较恢复，避免主动覆盖已不匹配的内容。 |

`EditorController` 的普通撤销是编辑器历史；事务恢复可以涉及多个文件及新建、删除，应通过变更服务而非编辑器快捷键完成。多文件执行不承诺跨文件原子性。

## 6. 续写、参考、主题和导出

### 光标续写

`EditorHost.vue` 按编辑事件调度自动预测，也可显式请求。自动预测默认开启，可在设置中关闭；只有 `prediction.auto` 为真才会在停顿后请求；手动入口是 AI 面板的「续写一句」。`useAgentStore.requestPrediction()` 在已有任务/候选等情况下不重复请求，向 Main 发送文稿修订、光标、选区及上下文选择。`PredictionService` 校验输入与版本，取光标前后片段、参考和风格说明，执行频控与缓存查找；新请求可中止之前的请求。候选返回后，界面复核活动文稿、修订和选区。`ghost.ts` 用装饰显示候选；`Tab` 接受才产生普通编辑，`Esc` 清除不写入。此流程不进入多文件提案审阅。

### 参考材料与附件

- `AttachmentService` 为任务图片等附件保存本地数据，视模型能力提供视觉输入。
- `ReferenceService` 把活动/已授权文稿、用户选择的文件、网页及图片材料转为带版本的来源记录及片段。PDF 片段可保留页定位；DOCX 提取正文；图片材料不等同于内置 OCR。
- `buildContext()` 根据查询与预算组织所选片段；角色区分事实、数据、写作风格和视觉风格。`applyCitations()` 校验生成文本中的来源标签（例如 `[S1]`），并使用上下文中可用的来源定位信息生成脚注；它不验证生成陈述是否被证据支持。
- `StyleService` 保存风格预设，提供文本说明和摘要；可参与显式任务及续写上下文，但不直接改写文稿或主题 CSS。

### 图片与文稿主题

插入图片时，渲染端把选中或粘贴的文件交给文稿服务；Main 以图片字节识别格式，将资源放入文稿资源目录并返回 Markdown 相对引用。实时预览/普通预览将相对引用解析为 `mdres`，导入主题资源用 `mdtheme`。未具备文稿路径或资源超出授权目录时，不应降级为渲染端直接读盘。`ThemeService` 导入 CSS 和允许的本地资源，借助共享作用域处理产生兼容报告；实时模式主要使用排版映射，独立预览和导出使用隔离样式。

### 导出

渲染端 `lib/exporter.ts` 负责用户动作、活动正文同步和导出参数；Main 的 `ExportService` 负责系统保存路径、磁盘写入及外部进程/打印。

- **Markdown**：原文导出直接保存；资源包经 `collectImageRefs()`、资源解析和路径改写后打包；内嵌模式把成功读取的本地图片转成 data URL。
- **HTML / PDF**：`buildExportHtml()` 组装正文、样式与可选主题；用导出渲染处理图表和资源。PDF 将组装好的 HTML 交给隔离打印窗口生成最终文件。
- **Pandoc**：主进程探测本机可执行文件，按转换方向读取源文件或生成临时输入。导入可把返回的 Markdown 打开成文稿；本机缺少 Pandoc 时只影响相关格式转换。

## 7. 存储、诊断和扩展

| 内容 | 负责模块与位置 |
| --- | --- |
| 文稿、本地图片 | 用户选择的文件系统位置；文稿同级资源目录名由设置指定。 |
| 应用设置、模型配置、写作风格 | `utils/paths.ts` 统一定位用户数据下的 JSON；对应服务维护默认值或更新。 |
| 模型密钥 | `SecretService` 使用 Electron `safeStorage` 保护持久化密钥；不可用时不写入明文凭据。 |
| 未保存草稿 | `DocumentService` 写入 `sessions/`。 |
| 提案、事务与备份 | `ChangeService` 管理 `changes/` 账本和 `recovery/` 副本；工作区删除也有自己的恢复路径。 |
| 主题、附件、参考 | 对应服务管理各自目录和索引，避免把资产存进文稿会话快照。 |
| 缓存与日志 | `configureCacheDir()` 解析缓存位置；`logger` 对消息做脱敏，附加字段仍须由调用方过滤。 |

维护时先根据问题确定所有权：编辑显示查 Renderer，磁盘结果查 Main，会话不同步查 IPC/Bridge，模型不产出结构化工具则核对 Provider 能力与任务事件。工作区和媒体相关逻辑应保留路径边界检查；网页来源应沿用 `references/web.ts` 的 URL、网络地址和跳转校验，不在渲染端直接绕过该服务。不要将原始密钥、模型鉴权头或用户正文添加到诊断日志。

**新增桌面能力**：先更新 `shared/ipc.ts` 的通道与方法契约，再实现服务、Main 校验和 Preload 白名单映射，最后接入状态库或组件。**新增变更类型**：同步修改 `ChangeOperation`、Zod 联合、规划/审阅、应用与恢复覆盖；只增加工具描述不会让操作安全可执行。**新增用户设置**：同时检查 `AppSettings`、`PartialSettings`、默认值、存取和界面绑定。

验证：`npm run typecheck` 运行 Main/Preload 与 Vue 类型检查；`npm test` 运行 `tests/unit/` 下的纯逻辑测试，涉及大纲、表格、变更、路径和网页校验、主题、预测、ZIP、图片重写。单元测试不等同于 Electron 窗口、真实 Provider、Pandoc 和安装包的端到端验证。当前未实现工作区向量检索/RAG 或独立 OCR 流程；分屏滚动按比例同步，导入主题亦不承诺与原主题像素级一致。
