# MarkdownIDE 产品需求文档

版本：V1.1 · 日期：2026-11-11 · 状态：开发前需求基线。

关联：[总体与 AI 集成方案](02-总体与AI集成方案.md) · [技术项目文档](03-技术项目文档.md) · [原型总览](../原型/原型总览.html)。

## 1. 产品定位

一款免费开源、本地优先的桌面 Markdown 编辑器。用户可以像使用 MarkText/Typora 一样直接编写和阅读文档，也可以通过自然语言与图片描述，让 AI 在当前文档或工作区其他文件中创建、修改和删除内容。

V1.1 文档扩充：支持内容续写与样式/结构预测，并将图片、网页链接和引用文件作为有来源的上下文辅助生成。基础参考材料读取不依赖 P2 工作区向量库；新增范围与验收见第 13 节。

产品重点为写作体验、Markdown 数据可移植性、Typora 文稿主题迁移，以及可控的 AI 文档操作。不把产品扩展成知识图谱、数据库或完整 IDE。

### 1.1 原始需求映射

| 用户需求                                    | 对应设计与需求编号           |
| ------------------------------------------- | ---------------------------- |
| 免费开源                                    | LIC-01、LOC-01               |
| 类 MarkText / Typora 的流畅交互             | EDT-01～EDT-05、UI-01～UI-06 |
| 精简、少冗余功能                            | 产品非目标、UI-07            |
| Typora 主题兼容                             | THM-01～THM-04               |
| 多格式导入导出                              | IO-01～IO-04                 |
| 本地、远程、官方模型                        | MOD-01～MOD-04               |
| 三栏、分屏、目录可缩放                      | UI-01～UI-05                 |
| Codex 风格浅色、可收起输入框                | UI-06、THM-01                |
| 指令驱动文档 CRUD、图片、链接等数据录入数据 | AGT-01～AGT-10               |

### 1.2 成功标准

- 用户可直接打开本地 Markdown 文件，无需注册账号即可编辑和基础导出。
- 同一文档在即时渲染、源码和分屏之间切换，不丢失语义和未保存修改。
- AI 能将描述转换为明确的文档操作，并展示实际目标文件和位置。
- 用户可以看到修改、接受或拒绝，也能恢复已接受的修改。
- 接入不同模型时，文档操作协议和用户工作流保持一致；能力不足时明确降级。

## 2. 范围与版本

P0：V0.1 必需；P1：V0.5 至 V1.0 完成；P2：V1.x 后续增强。V1.0 交付必须同时满足 P0 和 P1。

首期平台以 Windows 10/11 x64 为主要验收环境，macOS 与 Linux 在 V1.0 建立发布和回归矩阵。实际最低系统版本随选定 Electron 版本确认；不承诺已停止维护系统。ARM 安装包单独列入后续支持矩阵。

### 2.1 非目标

- 不训练或微调自有大模型；客户端免费不代表模型厂商 API 或外部推理资源免费。
- V1.0 不建立产品账号、付费套餐、官方推理代理或云同步服务。
- 不包括团队实时协作、移动端、白板、图谱、数据库、闪卡和任务管理。
- 不把任意系统命令执行、安装软件或访问整台电脑作为文档 Agent 的默认工具。
- 不承诺所有 Typora 主题像素级兼容，也不承诺 Word/PDF 与 Markdown 无损互转。

## 3. 用户与场景

目标用户包括技术作者、产品经理、学生、研究人员和希望控制模型来源的本地写作用户。

| 场景       | 用户动作                       | 预期结果                           |
| ---------- | ------------------------------ | ---------------------------------- |
| 日常写作   | 双击 Markdown，直接编辑        | 快速进入文稿，无账号或云服务阻断   |
| 内容搭建   | 从左侧拖入标题、表格等         | 插入到明确落点，光标可继续编辑     |
| 检查语法   | 切换源码/预览分屏              | 同一文档、选区与修改保持一致       |
| 图片转表格 | 附图并描述目标章节             | 提取数据，定位章节，预览表格后应用 |
| 跨文档整理 | 将当前文档行动项整理到指定文件 | 展示源文件、目标文件和变更         |
| 创建文稿   | 根据参考材料生成新文件         | 新建到指定位置，重名时不静默覆盖   |
| 删除文件   | 指令删除指定草稿               | 明确目标并确认，使用可恢复删除     |

## 4. 主界面与交互

### 4.1 布局要求

| 编号  | 优先级 | 需求与验收要点                                                                                            |
| ----- | ------ | --------------------------------------------------------------------------------------------------------- |
| UI-01 | P0     | 顶部全局工具栏包含文件、编辑、视图、帮助；下方为左/中/右三分区。                                          |
| UI-02 | P0     | 左侧上方提供元素/文件切换。文件区打开真实工作区；元素区支持点击与拖入正文。                               |
| UI-03 | P0     | 中间提供即时渲染、源码、源码/预览分屏；分屏只拆中间，不改变目录与左栏职责。                               |
| UI-04 | P0     | 右侧目录默认展开；点击定位、当前章节提示、拖动调宽、收起与恢复均可用。                                    |
| UI-05 | P0     | 左右侧栏独立调整宽度；在目标桌面分辨率不遮挡核心操作，不发生页面横向溢出。                                |
| UI-06 | P0     | AI 输入框位于编辑区底部中央，默认展开；上方下拉按钮向下收起，单行入口向上展开。占据布局空间，不覆盖正文。 |
| UI-07 | P0     | 专注模式可隐藏侧栏；低频功能进入菜单/命令面板，不常驻重型工作台。                                         |

以已交付原型为视觉参考：全局栏约 52px；左栏初始约 244px，右栏约 238px；正文最大宽度约 740px。尺寸是设计参考，正式版需结合可访问性、系统缩放及实际文本测量调整。

应用默认浅灰白背景、轻边框、线性图标和克制圆角，采用 Codex 截图呈现的轻量交互观感。深浅色切换应覆盖侧栏、菜单、弹窗与 AI；不让文稿主题污染应用工具栏。

### 4.2 AI 操作反馈

AI 面板显示当前作用范围（选区/当前文档/指定文件/工作区）、附件、Provider、模型与停止按钮。任务进度用简短步骤呈现：读取目标 → 识别图片 → 准备修改 → 待应用 → 已完成。

用户看到的修改摘要包括文件名、标题路径、操作类型和数量。例如：“接口说明.md → 请求参数，新增一个 4 行 2 列表格（含表头）”。展开可查看文字差异和渲染后结果。

## 6. 主题与转换

| 编号   | 优先级 | 需求                                                                                                             |
| ------ | ------ | ---------------------------------------------------------------------------------------------------------------- |
| THM-01 | P0     | 内置浅色/深色/跟随系统；支持字号、字体、行距、正文宽度自定义。                                                   |
| THM-02 | P1     | 导入 Typora CSS 及其本地资源，先预览再启用；失败可回退默认主题。                                                 |
| THM-03 | P1     | 分级兼容：A级为正文、标题、列表、表格、引用、代码、图片、任务；B级为公式、图表、目录、脚注；私有 UI 行为不承诺。 |
| THM-04 | P1     | 提供兼容报告；主题网络资源默认不加载；支持应用外观与文稿主题分离。                                               |
| IO-01  | P0     | 原生打开/保存 MD、TXT；导出 MD、带样式 HTML、无样式 HTML、PDF。                                                  |
| IO-02  | P1     | Pandoc 转换导入 DOCX、ODT、HTML、EPUB；导出 DOCX、ODT、EPUB、LaTeX。                                             |
| IO-03  | P1     | 导出 Profile 支持主题、模板、资源策略、纸张与页边距；缺少转换器时给出定位/安装引导。                             |

PDF 输入、扫描件 OCR 与保留原版式不是 IO-02 的默认承诺。DOCX 使用参考文档样式，LaTeX 使用对应模板，不能宣称它们直接复现 Typora CSS。PDF/HTML 优先复用 Chromium 与文稿打印样式。

## 7. 模型接入需求

| 编号   | 优先级 | 需求                                                                                          |
| ------ | ------ | --------------------------------------------------------------------------------------------- |
| MOD-01 | P1     | Local：本机 Ollama、LM Studio 等服务，提供连接检测与明确地址。                                |
| MOD-02 | P1     | Custom Remote：用户指定远程地址、模型和认证；不假设兼容接口支持所有能力。                     |
| MOD-03 | P1     | Official：使用模型厂商官方接口适配器；首个参考适配器为 OpenAI，其他厂商在统一接口下增量开发。 |
| MOD-04 | P1     | 标识并实测视觉、工具调用、结构化输出、流式能力；不足时解释降级或要求换模型。                  |

“官方”指模型厂商官方 API，不指应用方免费提供模型额度。配置用户自己的凭据；不把应用方通用密钥打包进入客户端。

支持视觉的模型直接读取附件；文本模型可选接入本地 OCR，但复杂表格结构恢复另行验证。接口能连通不等于 Agent 用例通过。

| AGT-07 | P1     | 修改前展示文件级摘要与差异；支持接受、拒绝、取消；当前文档可选择低风险自动应用。 |

| AGT-10 | P1     | 任务可停止；请求超时、限流、工具失败有可恢复反馈；重试不重复插入或重复创建。     |
| AGT-11 | P2     | 工作区语义检索、Embedding/RAG、复杂长任务与可公开扩展工具。                      |

### 8.1 目标定位语义

- “二级标题”明确表示 H2；“第二个标题”按当前目录计数规则显示候选，有歧义先澄清。
- “标题后”表示标题行结束后的正文起始位置。
- “章节尾部”表示下一个同级或更高级标题之前；下级标题属于该章节。
- “段落尾部”表示指定段落末尾，不等同于章节尾部。
- 目录折叠、过滤不改变标题实际文档顺序。
- 重复标题通过上级路径、正文摘要和内部 ID 区分；ID 仅在对应文档版本内有效。

### 8.2 4×2 表格规则

界面统一显示“行 × 列”。Markdown 表格有表头，因此应显式约定总行数是否包含表头。未约定且会影响结果时，使用轻量澄清：“4 行包含表头吗？”

验收用例固定为 4 行 2 列、含 1 行表头和 3 行数据。分隔符行不算内容行。图片数据过多时不得静默截断；不足时允许留空并说明；无法辨认时显示“待核对”，不要自动猜测。合并单元格转为标准 GFM 时解释展开策略。

## 9. 权限、隐私与恢复

默认工作范围是用户显式打开的文件/工作区。使用文件 ID 访问经校验路径；工作区外文件需用户主动选择。只发送任务必要的文稿范围和用户提供附件，界面展示实际发送范围。

文档和图片是数据来源，不是授权来源；其中的“忽略指令”“删除其他文件”等文字不能扩大权限。密钥不得进入 Renderer、普通配置导出或诊断日志；无法安全持久保存时支持仅本次会话使用。

默认变更先预览；可选择自动应用当前文档的低风险内容修改。文件删除、覆盖重名文件和多文件任务仍显示明确目标与确认。不能用模型声称“用户已同意”替代应用内确认记录。

对未保存文档的 AI 修改先进入编辑器并标记 dirty，按用户保存策略落盘；未打开文件写入前检查磁盘指纹。恢复操作也检查版本，不能覆盖用户在 AI 修改之后新增的内容。

## 10. 非功能指标

以下为目标，必须在真实应用完成后测量，不能引用原型作为证据。

| 类别       | 指标与测量条件                                                                      |
| ---------- | ----------------------------------------------------------------------------------- |
| 参考环境   | Windows 11 x64、4 核 CPU、16GB RAM、SSD、100% 系统缩放；记录硬件与构建号            |
| 启动       | 冷启动到可输入 P95 ≤ 2.5s，热启动 P95 ≤ 1.2s；独立运行各 30 次                      |
| 输入       | 1MB 混合 Markdown 按键到绘制 P95 ≤ 50ms；图片/图表按需渲染                          |
| 大文档     | 10MB 语料可打开、搜索、保存；若降级到源码模式需明确提示                             |
| 内存       | 空白单窗口进程树稳定目标 ≤ 350MB；1MB 常规文档目标 ≤ 500MB，记录稳定窗口与进程总量  |
| 模型任务   | 生成与导出期间界面可编辑；展示首事件时间，不对外部模型耗时作绝对承诺                |
| 数据完整性 | 保存冲突、取消、异常退出和失败重试测试不造成未提示的数据丢失                        |
| 可访问性   | 核心操作可键盘完成；普通正文/控件文本目标对比度 ≥ 4.5:1，不能直接照搬原型过浅提示色 |

## 11. 验收场景

| 用例             | 关联需求       | 操作与通过条件                                                                                    |
| ---------------- | -------------- | ------------------------------------------------------------------------------------------------- |
| AC-01 三栏       | UI-01～UI-06   | 切元素/文件、拖放、目录调宽收起、AI 收起展开后布局正确                                            |
| AC-02 往返       | EDT-02、EDT-05 | 中英混排、表格、引用、Front Matter 多次切模式，语义不丢失、撤销连续                               |
| AC-03 未保存内容 | FIL-02、AGT-01 | 先编辑不保存，再请求摘要，模型工具读到最新缓冲区                                                  |
| AC-04 图片填表   | AGT-02、AGT-03 | 已明确第二个 H2、含表头 4×2，表格位于该章节尾；8 个内容单元格与清晰图片金样一致                   |
| AC-05 定位歧义   | AGT-02、AGT-04 | 重复标题、同名文件、含糊行数先澄清，确认前无写入                                                  |
| AC-06 并发编辑   | AGT-08         | 提案后用户修改目标段落，旧提案被阻止或重新生成并展示                                              |
| AC-07 新建       | AGT-05         | 新建到指定目录；已有同名文件内容不被静默覆盖                                                      |
| AC-08 删除       | AGT-06、AGT-09 | 显示文件路径并确认；处理 dirty；恢复文件不覆盖后来同名文件                                        |
| AC-09 重试       | AGT-10         | 网络断开与重试后无重复插表、重复建文件                                                            |
| AC-10 多文件失败 | AGT-09         | 故意制造只读/磁盘失败，展示已成功、未执行、需恢复文件，记录可恢复                                 |
| AC-11 主题       | THM-02～THM-04 | 固定 10 个有可用许可的主题，每个覆盖 A 级元素；预先登记检查点通过率 ≥95%，无不可编辑/不可恢复故障 |
| AC-12 导出       | IO-01～IO-04   | 中文、图片、表格、公式/图表金样按格式验证；链接与资源可访问，损失项有说明                         |
| AC-13 Provider   | MOD-01～MOD-04 | 实际本地、远程自建、官方三类配置各跑契约与代表用例，能力缺失可解释                                |

AI 发布评估采用至少 40 个固定任务，覆盖清晰成功、歧义、失败、并发和误导数据；正常语义任务端到端目标成功率 ≥90%。关键约束以应用校验和确定性测试保证：未授权文件访问、静默覆盖、重复应用不允许出现。每个 Provider/模型单独记录结果，不能跨模型套用成功率。

## 12. 阶段出口与开放项

- 技术验证：确认 Muya 接口、三模式一致性、主题 A 级映射和单次图片填表闭环可行。

## 13. AI 预测与参考材料生成（V1.1 文档新增）

本节 P1 纳入产品 V1.0 交付。此前 AGT-11 的 P2 指工作区规模的语义检索与长任务，不延后本节已选材料的基础检索和引用。

### 13.1 预测的定义与边界

“预测”包括三类：内容预测（下一句、下一段、列表项、标题）；结构/写作风格预测（沿用术语、语气、标题层级、列表和表格表达）；视觉样式建议（正文样式、主题和排版配置）。不宣称知道用户未表达的真实意图。

写作风格与事实依据分开：模仿示例的语气和章节结构，不自动采用示例中的数字、产品名或事实。视觉样式先预览，用户接受后通过外观/主题设置应用，不执行模型生成的任意脚本或直接覆盖主题文件。

默认提供手动触发预测；自动预测需用户主动开启，可按文档/工作区暂停。自动模式首次配置明确模型、发送范围与调用频率，此后在该范围内运行，不逐次打断询问。不得默认扫描历史文稿或自动建立用户画像。

| 编号 | 优先级 | 需求与验收要点 |
| --- | --- | --- |
| PRE-01 | P1 | 在当前光标处展示一句/短段的幽灵文本续写，区分建议与已写正文；未接受不保存、不计字数、不进入导出。 |
| PRE-02 | P1 | 基于当前章节、上下文和用户选择的风格样例建议标题、列表、表格或后续结构；不能自行覆盖正文。 |
| PRE-03 | P1 | 预测正文视觉样式时展示主题/排版候选和应用范围；与内容修改分开预览，可恢复原设置。 |
| PRE-04 | P1 | Tab 接受当前建议，Esc 忽略，继续输入/移动光标使失效建议消失；表格、代码缩进和 IME 优先保留编辑器原有按键行为。 |
| PRE-05 | P1 | 预测默认可手动触发，自动模式可关闭/暂停；不在中文组合输入期间请求或抢占候选。限制频率、预算并支持取消。 |
| PRE-06 | P1 | 结果绑定文档版本、光标、参考资料和风格配置；过期结果丢弃。接受后一次撤销，拒绝不留下正文变更。 |

### 13.2 图片、链接与引用文件

AI 面板“添加参考”支持图片、链接、文件，以及 `@文件` / `@章节`。每份材料显示标题、类型、解析状态和用途标签，可移除、替换或限定范围。读取参考资料不授予编辑或删除该资料的权限。

支持四种用途：事实依据、待提取数据、写作风格、视觉样式。默认文件/链接为事实参考，图片由用户选择数据或样式；同一材料可声明多个用途，但事实生成只能依据具有事实/数据用途的实际片段。

| 编号 | 优先级 | 需求与验收要点 |
| --- | --- | --- |
| REF-01 | P1 | 图片可粘贴/拖入；文件可选择或 @ 引用；链接可粘贴后明确选择“读取为参考”。普通正文链接粘贴不自动联网。 |
| REF-02 | P1 | 已打开 MD/TXT 读取最新会话内容；DOCX、文本型 PDF 可提取段落/页。扫描 PDF 需 OCR/视觉能力，缺失时显示受限。 |
| REF-03 | P1 | 公开 HTTP(S) 链接在用户选择后提取正文，显示实际 URL、标题、抓取时间和可用状态；认证、付费或动态内容读取失败不假装已读。 |
| REF-04 | P1 | 每份材料可选择用途、页/章节范围与启用状态；参考源默认只读；更换发送的模型/远程目的地时检查现有授权范围。 |
| REF-05 | P1 | 事实段落的建议来源可展开到网页片段、文件页/标题或图片区域；插入时可选择生成 Markdown 脚注/来源列表。不能只给出不可定位的文件名。 |
| REF-06 | P1 | 材料矛盾、缺失、过期、OCR 不确定或上下文裁剪时显示提示，关键数据不足时请求补充或标注“待核实”，不伪造引用。 |
| REF-07 | P1 | 解析大文件时可选页/章节、搜索相关片段；展示哪些材料/片段实际用于本次生成，避免宣称“已完整阅读”被截断文件。 |
| REF-08 | P1 | 默认仅处理显式选入的材料；网页和文档内容不能改变工具权限。材料可移除并清除本地缓存，说明移除不等于撤回已发给远程模型的请求。 |

DOCX/PDF 参考解析与 IO-02 的“转换成可编辑 Markdown”是两个功能；引入 PDF 参考读取，不扩展为 PDF 原版式编辑。暂不将 PPTX、XLSX、网盘/登录站点、递归网站抓取作为 V1.0 必需支持。

### 13.3 高质量生成交互

任务输入除描述外，可选生成目标（摘要/段落/章节/整篇）、受众、长度、风格、引用要求。默认从当前文档延续语气；用户可固定工作区写作规范，显式指令优先。

示例：“参考这张界面图的简洁风格、这两个链接的事实和 @产品需求 的术语，续写当前章节的实施建议。”界面将材料标注为“样式参考 / 事实依据 / 术语与风格”，展示实际读取情况，生成后查看内容与来源，再通过原有 ChangeSet 应用。

自动预测仅使用已解析且已授权的当前上下文，不在每次击键时重新抓网页或上传整份附件。复杂多材料生成走显式 Agent 任务，允许更充分的检索与校验。

### 13.4 新增验收与指标

| 用例 | 关联需求 | 通过条件 |
| --- | --- | --- |
| AC-14 预测接受/拒绝 | PRE-01、PRE-04、PRE-06 | 未接受内容不落盘/导出；接受后是一次编辑，可撤销；Esc 和继续输入能清除建议 |
| AC-15 过期与 IME | PRE-04～PRE-06 | 生成期间移动光标/修改文稿/更换材料后，旧结果不出现；中文候选确认不误接受预测 |
| AC-16 样式与风格 | PRE-02、PRE-03、REF-04 | 沿用指定写作风格；视觉主题独立预览；风格样例中的无关事实不会自动进入正文 |
| AC-17 混合来源 | REF-01～REF-05 | 图片、网页和文件共同生成，来源均能定位；没有读取的材料不显示为已引用 |
| AC-18 不可读/矛盾材料 | REF-03、REF-06、REF-07 | 404、认证页、扫描页和互相冲突的数字得到明确反馈，无伪造读取成功或引用 |
| AC-19 范围与缓存 | REF-04、REF-08 | 移除材料使预测和提案失效；参考文件未被意外修改；恶意网页不能扩大工具范围 |

预测初始调度目标：停顿约 800ms 后触发、每会话仅 1 个在途请求、自动调用不高于每分钟 6 次，均可配置。建议缓存命中展示 P95 ≤100ms；网络预测统计完整候选可用时间，不对任意外部模型保证固定延迟。显式任务优先，预测不得使基础输入延迟超过第 10 节指标。

在原 40 个 Agent 任务之外新增至少 20 个预测/参考用例。记录建议曝光、接受、取消与过期丢弃等本地指标，默认不上传内容或行为画像。事实质量评估包含来源定位、数据一致性和引用是否支持该陈述；只验证链接存在不能视为事实已核实。
